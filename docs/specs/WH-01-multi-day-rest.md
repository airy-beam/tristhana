## 1. Scope
**In:** a **rest period** started from a 🌸 / 🤒 / ✈️ day (today or yesterday) with one question "for how many days?"; its days show as that status unless something else is logged; practice reminders skip them; end early; "keep the pause" after logging a practice inside one; reminder 🧘/😌 never overwrite (Q26); a "hide the 🌸 button" account setting (bot grids incl. `/start`, Mini App chips).
**Out:** periods for plain 😌 rest or "No practice"; a free-text day count; backfilling a past range in one go (log day by day as today); pausing moon reminders; cycle prediction (WH-03); teacher views (ST-06 consequence in ADR-0023); a period list/history screen.

## 2. Rules
- **Model: stored range, derived days** (ADR-0023). A `RestPeriod(start, end, kind)` is the person's statement "these days are 🌸". Days are never written to `day_log`. Read-time precedence for a date ≤ today: **logged > period > moon > day off**. Days are calendar days: a moon day or the day off inside a period counts as one of the N days (nothing shifted, nothing added; ADR-0022).
- **Offer (when the question appears).** After a tap on 🌸/🤒/✈️ for date D, iff: D ∈ {today, yesterday} (local; provisional zone allowed, as for logging); D isn't covered by a period, or D is the `start` of the period covering it (a re-tap or a corrected kind may re-choose); and it isn't a *continuation*: D−1 isn't the same status (logged or period-covered), **except** when D−1 is the last day of a same-kind period (the pause ran out: ask again). Past days (≤ D−2): never asked.
- **Choosing N** creates `[D, D+N−1]` (D itself is already logged). **Per kind** (owner): 🌸 first screen **2 · 3 · 5**, "Other…" **4 · 6 · 7** (max 7); 🤒/✈️ first screen **3 · 4 · 5**, "Other…" **2 · 6 · 7 · 10 · 14** (max 14). The allowed set is a domain table; callback decoding, the API and the use case all reject any other N for that kind. A new period replaces what it overlaps: an earlier period covering D ends at D−1 (removed if that leaves only its start day), periods starting inside `[D, end]` are removed. Coverage never overlaps. No merge/extend: a pause that ran out is followed by a new adjacent period.
- **Logging inside a period.** Any status wins for its day. **🧘 Practiced on day d** ends the period at d−1 (on its start day it removes the period). **🌱 No practice and other rest-like statuses change only that day.** **Clearing the start day** removes the period (its statement is gone); clearing a later day shows the period status again.
- **Keep the pause (undo).** When a 🧘 save cut a period that still had days after d (`end > d`), the saved/details screen adds a gentle line and `[⏸ Keep the pause]`, which restores the period exactly as it was (`start`, `end`, kind) while d stays practiced. Neutral tone: practising on such a day is fine; the line only says what changed. The callback carries the period itself (`a1:k:<start>:<end>:<kind>`, 25 bytes), so it is stateless. It's a no-op once `end < today` (nothing left to keep), and the restore uses the same overlap rule as a new period.
- **End early** (from the day screens, `/remind`, Today card): the period stops covering today and later days: `end = today − 1`, removed if that leaves ≤ 1 day. Past covered days stay. Label "⏹ End the pause" with practice reminders on, "⏹ End early" with them off.
- **Reminders.** Practice reminders skip covered dates (like logged days). **Moon reminders keep coming** (owner): they're about an upcoming rest day, ~4/month, and come first under the shared cap, which paused days only free up. `_silent` (10 unanswered → note + off) treats a covered date as answered, and any covered date after the oldest of the 10 counted reminders resets the run (starting a pause is an answer).
- **Reminders off / never chosen:** the same question with fill-only wording (`$reminders = off`); WH-01's range is useful without reminders.
- **Q26 (closed):** the reminder's 🧘 and 😌 become `r1:p:<date>` / `r1:r:<date>`, insert-if-absent like ✅ (`INSERT … ON CONFLICT DO NOTHING`; 😌 is sealed as a rest row). An already-logged day shows V for the stored status with `[✏️ Change]`. Reminders already in chat history keep their `d1:s` buttons (known limit, they can't be edited after sending).
- **Stats** (ADR-0020): covered unlogged days ≤ today are fed to `domain/stats.py` **as rest-like days of their kind**: cells show the kind (🌸 drawn as rest unless the device switch is on, unchanged), summaries count `rest[kind]`, never `unlogged` nor `auto`; runs treat them as **marked** rest (transparent, gap reset), unlike PR-09's auto days. Each period is a fresh statement made today or yesterday (never backfilled), so a run continues only while the person keeps telling us about their days; chained periods can bridge a long break, and that's fine: runs are personal and non-competitive (no leaderboards).
- **Hide 🌸** (`account.hide_ladies`, default false): the 🌸 button is left out of the bot status grid (`/log`, `/start`, the picker) and the Mini App chips (Today, DayEditor), **except on a day whose shown status is 🌸** (so ✓/pressed stays visible). Old `d1:s:…:l` keyboards keep working. Logged 🌸 days and the device-only "Show 🌸 days" switch are unaffected.

## 3. Domain (pure) `domain/rest_periods.py`
```python
PAUSABLE = frozenset({DayStatus.LADIES, DayStatus.SICK, DayStatus.TRAVEL})
PAUSE_DAYS: dict[DayStatus, tuple[tuple[int, ...], tuple[int, ...]]] = {   # (first screen, Other…)
    LADIES: ((2, 3, 5), (4, 6, 7)), SICK: ((3, 4, 5), (2, 6, 7, 10, 14)), TRAVEL: ((3, 4, 5), (2, 6, 7, 10, 14))}
def max_days(kind) -> int                      # 7 / 14; MAX_PERIOD_DAYS = 14 (the DB cap)
@dataclass(frozen=True) class RestPeriod: start: date; end: date; kind: DayStatus  # inclusive, end > start
@dataclass(frozen=True) class PauseOffer: start: date; kind: DayStatus; reminders_on: bool
class InvalidRestPeriod(ValueError)
def check_period(start, days, kind, now, zone) -> RestPeriod      # kind ∈ PAUSABLE, days ∈ PAUSE_DAYS[kind], start ∈ [today−1, latest_loggable]
def check_restore(period, now, zone) -> RestPeriod | None          # length ≤ max_days(kind); None if end < today
def pause_offer(day, today, status, prev: DayStatus | None, covering: RestPeriod | None,
                before: RestPeriod | None, reminders_on: bool) -> PauseOffer | None   # §2 rule
def place(new, existing: Iterable[RestPeriod]) -> Placement(removed, ended: dict[date, date])  # overlap rule
def cut_by_log(p, day, status | None) -> RestPeriod | None | Unchanged   # only PRACTICED cuts; clear on start removes
def end_from(p, today) -> RestPeriod | None
def covered_days(periods, start, end, today, logged) -> dict[date, DayStatus]  # unlogged, ≤ today
```
`auto_days(…, covered: Set[date] = ∅)` skips covered dates. `Candidate.paused: frozenset[date]`; `due_practice_reminder` returns None for `day in c.paused`. `Account.hide_ladies: bool = False`. The SQL in §4 implements `place`/`cut_by_log`; a shared case table runs in the domain and the DB tests (parity). The per-kind limit lives in the domain only (the kind is sealed, so the DB CHECK is the 14-day cap).

## 4. Application and infrastructure
- **`SetDayStatus.execute` → `DaySaved(day, offer: PauseOffer | None, period: RestPeriod | None, cut: RestPeriod | None)`** (`period` = the one now covering `day`, `cut` = the period as it was before a 🧘 cut, for "keep the pause"). The upsert stays **one statement**: CTEs apply `cut_by_log` (DELETE/UPDATE `rest_period` only when the status is practiced, kind-agnostic), and `RETURNING` carries scalar subqueries read from the pre-statement snapshot: D−1's `status`/`sealed_status`, the periods covering D−1..D (start, end, sealed kind) and `practice_on`. The repository unseals; the use case calls `pause_offer`. `ClearDayStatus` adds the "clear the start day" CTE (still 1 statement). `insert_if_absent` (✅, `r1:p`, `r1:r`) gets the same cut CTE and returns `cut` too.
- **`StartRestPeriod(principal, start, days, kind) -> RestPeriod`**: `check_period`, then one statement: `INSERT … ON CONFLICT (account_id, start_date) DO UPDATE` + CTEs for `place`. Raises `InvalidRestPeriod`, `DateInFuture`. **`RestoreRestPeriod(principal, period) -> RestPeriod | None`**: `check_restore`, then the same statement. **`EndRestPeriod(principal, start) -> RestPeriod | None`**: one `UPDATE … RETURNING` or `DELETE` per `end_from` (`CASE` on `today − 1 − start_date`); idempotent.
- **Reads:** `range_with_moon` and `history` add a periods subquery (`start_date BETWEEN from − 13 AND to AND end_date >= from`, a PK range thanks to the 14-day cap); `range_with_moon` also returns `practice_on` (labels on covered days): still one statement each. `GetDays` returns `periods` and passes `covered` to `auto_days`; `GetYearStats` merges `covered_days` into `days` before `year_stats` (no `stats.py` change).
- **Tick:** `candidates`' logged-days statement gains a `UNION ALL` of covered dates (`generate_series(greatest(start_date, :from), end_date, '1 day')` for accounts with `practice_on`), flagged `paused`: **no new statement**. The notification settings read (`/remind`, API) adds a scalar subquery for the period covering today (`paused_until`).
- **Hide 🌸:** `ProfilePatch.hide_ladies` via the existing `UpdateProfile` (ADR-0021 partial; 1 UPDATE … RETURNING).
- No new policy: every call is the caller's own data (`Principal`), as in PR-01.

## 9. Cross-cutting checks
- **Time zones:** periods are local dates in the account zone ("today" as for logging; provisional allowed). The tick checks coverage against the local date in the **current** zone, so a travel zone change moves nothing; crossing the date line can shift a pause edge by a day (accepted, as `day_log`). Only dates are shown ("through Wed, Oct 28"), so no time/zone label applies. "Keep the pause" compares `end` with today in the current zone. Tests: Kiritimati vs Honolulu on the same instant, provisional `ru`/`en`, a pause spanning a Berlin DST change.
- **Privacy:** the **kind is sealed on every period** (`l`/`k`/`t`, same 42-byte length, AAD = `rest_period.sealed_kind|account_id|start_date`), so a 🌸 period is indistinguishable from sick/travel in the DB; dates stay plain (needed for SQL; the same residual date pattern `day_log` rest rows already show, ADR-0016). A 7-day max only for 🌸 is enforced in the domain, not by a DB CHECK, so the length never hints at the kind beyond the dates themselves. Teacher/aggregate paths (ST-06/08) must show covered days as plain "rest", never the kind (ADR-0023). The week picker shows 😌; 🌸 appears only on the person's own day screens. Callback data reuses PR-01's `l` code (no new exposure). Reminder 😌 (`r1:r`) is sealed like any rest row. Logs: account uuid only, never kind or N.
- **i18n:** all keys in `bot.ftl`/`app.ftl` with en/ru parity; `pause-days` uses Fluent plurals (RU 2/3/4 «дня», 5/6/7/10/14 «дней»); dates via `DateArg` (Babel); RU «ты», no gendered past tense, „…“ for quoted labels; "through" / «по … включительно» for the inclusive end; reminders-off variants for every pause line and button.

## 12. Implementation notes (2026-10-27, after code review)
- **Restore gate:** "keep the pause" (`a1:k`, `PUT /me/rest-periods/{start}`) only writes when a 🧘 Practiced day lies in [start, min(end, today)], checked in the same statement (`INSERT … SELECT … WHERE EXISTS`, the overlap CTEs gated alike). A forged keep can't backfill rest days; it answers `period: null`.
- **Serialised writes:** `place` / `restore` take `pg_advisory_xact_lock` per account in their transaction, so two taps at once can't create overlapping coverage. The pause read orders by start and takes one row, should two ever overlap.
- **One statement per tap, as specified:** choosing N returns the reminders flag from the `place` statement; ending early returns the removed period's kind from the same statement (`DELETE … RETURNING`); `/remind` time and on/off taps (and `PATCH /me/notification-settings`) return the covering period in the upsert's RETURNING, so "Paused through" stays; Keep carries the 🧘 day and reads only it. "Today" for these reads comes from the use case's clock.
- **Unreadable seal:** a period whose kind can't be decrypted is sent as `kind: "rest"` (output enum only) and covers its days as plain rest; Keep isn't offered for it.
- **Accepted deviations:** `pause-cut` has a third `$rel` variant (`other`, "that day") for a 🧘 logged further back; the Mini App's `.ftl` spells out each `pause-*` variant in full (Fluent isolation would otherwise wrap the nested variant words).
- **Mini App:** a day save also refreshes the notification settings (a 🧘 may have cut the pause); with "Show 🌸 days" off, a cut 🌸 pause is named as rest in the day editor.
