# ID-06 + NT-01/NT-02 surfaces: settings (name, language, time zone, moon calendar, notifications, privacy)

- Status: **accepted** (owner: all yes, 2026-10-19) · Date: 2026-10-19
- Requirements: **ID-06** (profile: display name, language, time zone, moon-day calendar, privacy settings), **NT-01** (moon + practice categories, one place), **NT-02** (quiet hours, daily cap). Settles **Q24** (moon intro flag) and **Q25** (PUT freezes defaults); touches UI-04 (Back/Settings buttons). Roadmap: "Settings: language, zone, moon calendar, notifications". Budget: < 300 ms p50 per tap (warm).
- Related: ADR-0005 (time), 0008 (stateless callbacks), 0015 (accounts), 0016 (sealed 🌸), 0018 (tick), 0019 (cities). New: **ADR-0021** (settings writes are partial; explicit choices are never overwritten by client data; Proposed).

## 1. Scope
**In:** a lazily loaded Mini App **Settings** screen that gathers every setting in one place; a bot **`/settings`** screen (language, time zone by city, links to the existing moon and practice reminder screens); `PATCH /api/v1/me` and `PATCH /api/v1/me/notification-settings`; a **travel prompt** on Home when the phone's zone differs from the account's; migration 0006 (two "custom" flags, the moon intro flag, and nulling values that only repeat the defaults).
**Out:** export/delete (ST-09), teacher links and per-teacher sharing (Phase 3), the weekly day off (PR-09), searching all IANA zones, the "Follow Mysuru moon days while you're here?" prompt (MD-02/04), RU city names in time labels (Q22), the onboarding flow (UI-01 item), a per-chat command menu language.
**Cut if time is short:** the travel prompt (the zone can still be changed in Settings), and the bot's zone picker (the Mini App covers it).

## 2. Flows and copy
- **Entry (Mini App):** Home row `settings-open` "⚙️ Settings" under "📊 My practice", plus Telegram's own **Settings item in the ⋯ menu** (`settingsButton`, shown while the app is open) → view state `settings` (no router, like Stats). Telegram's BackButton (or the on-screen "‹ Back" fallback) returns Home. **Home gets lighter:** Today card, "My practice", a slim moon card (next 3 moon days + 📍 city, no controls), "Settings". The city picker, the moon reminder chips and the practice reminder card move to Settings.
- **Settings screen (360 px, top to bottom):**

  3. **Moon days.** The city select moved from MoonCard, plus the existing `moon-calc-note`.
  4. **Reminders.** Moon: offset chips 7/3/1 and **time chips 07·12·19·21** (new in the Mini App). - **Travel prompt (Home, Mini App):** on open, if the device zone is valid, isn't UTC, and its **current UTC offset differs** from the account zone's (so `Europe/Kiev` vs `Europe/Kyiv` never nags), Home shows `zone-travel` with `[Switch to Bangkok] [Keep Almaty]`. **Keep** is remembered on the device per device zone (`localStorage tz.keep = "Asia/Bangkok"`), so it returns only when the phone moves again. ## 3. Design
**Domain (pure).**
- `Account` gains `name_custom: bool` and `locale_custom: bool`. `profile_refresh` **skips the name when `name_custom`** and **the locale when `locale_custom`** (ADR-0021). `last_seen_at` is still refreshed.
- `ProfilePatch(display_name, locale, timezone)`: each field is `KEEP` (a sentinel), a value, or `None` = "back to Telegram" (name and locale only). `resolve_profile(account, patch, client: ExternalProfile) -> ProfileChange`: the name goes through `normalize_display_name`. Blank or `None` → the client's first name with `name_custom=False`. A raw name longer than 64 → `InvalidDisplayName`. Locale `None` → `negotiate_locale(client.language_code)` with `locale_custom=False`. The zone goes through `parse_timezone` (UTC allowed here, as an explicit choice) and raises `InvalidTimezone`.
- `NotificationPatch`: moon offsets/at, quiet (start, end) as a pair, daily_cap, practice on/at/days. Each field is `KEEP`, a value, or `None` = back to the default (stored NULL). `apply_patch(stored: StoredSettings, patch) -> StoredSettings`, then `effective(stored, DEFAULTS)` → `check_settings` (the **merged** result is checked, so quiet hours are checked against the stored reminders and vice versa).
- `offsets_differ(a, b, now)` for the travel prompt is computed **client-side** in TS (`Intl`). There's no server rule.

**Application.**
- **`UpdateProfile(accounts).execute(principal, patch, client) -> Account`**: one `UPDATE … RETURNING`. Both adapters already hold the `ExternalProfile` (bot: `from_user`; API: initData), so the middleware/deps put it next to the account. `RecordDeviceTimezone` and `UseCityTimezone` stay "only if unset".
- **`PatchNotificationSettings(notifications).execute(principal, patch) -> NotificationSettings`**: reads the stored row (nullable columns), applies the patch, checks, then upserts **only the patched columns** (2 statements). `UpdateMoonReminders` and `UpdatePracticeReminder` become thin wrappers over it, which also fixes their probe that ignored custom quiet hours. `NotificationSettingsUseCase.save` (PUT) stays as is until PUT is removed.
- **`GetSettingsView`** (bot S): account (already loaded) + settings + city → **1 statement**.
- Ports: `AccountRepository.update_settings(id, ProfileChange)`, plus `update_profile` keeps custom fields in SQL (`CASE WHEN name_custom THEN display_name ELSE :new END`), so a concurrent refresh can't undo a choice. `NotificationRepository.stored(id) -> StoredSettings` and `patch(id, columns)`. **Q24:** `candidates` reads `moon_intro_sent_at IS NULL` instead of joining deliveries, and the tick's `finish(sent)` for a moon intro also sets `moon_intro_sent_at` (the same statement, via a CTE).

**API** (initData auth, own account).

| Method, path | Request | Response |
|---|---|---|
| `GET /api/v1/me` | none | `Me` + `name_from_telegram: bool`, `locale_from_telegram: bool` |
| `PATCH /api/v1/me` | any of `display_name: str \| null` (≤ 200 raw), `locale: "en" \| "ru" \| null`, `timezone: str` (IANA or `UTC`); null = back to Telegram; omitted = unchanged | 200 `Me`; 422 `invalid_timezone`, `invalid_display_name` |
| `PATCH /api/v1/me/notification-settings` | any of `moon: {offsets?, at?}`, `quiet: {start, end} \| null`, `daily_cap: int \| null`, `practice: {on?, at?, days?}`; inner `null` = default, omitted = unchanged (`model_fields_set`) | 200 `NotificationSettingsOut`; 422 `invalid_settings` |
| `PUT /api/v1/me/notification-settings` | unchanged, **`deprecated: true`** | unchanged; removed in the first release after this one (cached bundles) |

The Mini App sends only what was tapped (`{moon: {offsets: [7, 1]}}`), so the optimistic queue no longer needs `withPractice`. A zone change invalidates `["days"]`, `["stats"]`, `["moon"]` and the settings. A locale change re-renders through `Session` (both bundles are already loaded).

**Bot** (`bots/telegram/settings.py`, `settings_callbacks.py`, prefix **`s1:`**; answer in parallel, edit as the webhook reply).

| Data | Meaning | Max bytes |
|---|---|---|
| `s1:v` | screen S | 4 |
| `s1:l:a` / `s1:l:en` / `s1:l:ru` | language: auto / explicit (absolute) | 7 |
| `s1:zp:2` | zone city picker, page | ≤ 8 |
| `s1:z:<slug>` | set zone = that city's zone (slug ≤ 24) | ≤ 29 |

**Round trips:** S = middleware + 1. A language or zone tap = middleware + 1 (UPDATE RETURNING) + 1 (settings read for S).

**Mini App.** `screens/settings/Settings.tsx` (lazy) with `ProfileSection`, `ZoneSection`, `RemindersSection` (moon chips + the moved `PracticeReminderCard` + quiet/cap), `PrivacySection`. `TravelPrompt.tsx` on Home (initial bundle). `useSettingsButton(onOpen)` in `telegram/index.ts`. Hooks `usePatchMe`, `usePatchNotificationSettings` (optimistic, scope `"settings"`). Estimate: initial JS **−1 to −2 KB** (controls leave Home), lazy chunk ~5 KB gzip. No new dependency.

## 5. Migration `0006_settings` (expand-only)
- `account` add `name_custom boolean not null default false`, `locale_custom boolean not null default false`.
- `notification_settings` add `moon_intro_sent_at timestamptz null`. Backfill: set it to the earliest `sent` moon delivery per account (an account whose deliveries are already pruned sees the intro once more, as today).
- **Data (Q25):** set to NULL the columns whose stored value equals today's default (`moon_offsets = {1,7}`, `moon_at = 19:00`, `quiet 22:00/07:00` as a pair, `daily_cap = 3`). The effective settings don't change, and later default changes then apply. Practice columns aren't touched.
- Downgrade: drop the columns (the nulling is harmless and isn't reversed).

## 6. Cross-cutting checks
- **Time zones:** explicit choices only. The device zone is stored silently only when none is set (ID-01), and is otherwise offered via the travel prompt. Logged days keep their `local_date` and stored `timezone`. Practice start times keep their own zone. Reminders recompute every tick, and the dedupe key is the local date, so a same-day move east or west never sends twice. UTC is selectable only explicitly. Every shown time uses `TimeArg` / `zoneLabel`. Tests: switching Almaty → Bangkok after the 10:00 reminder (no second one), Kolkata +5:30 and Kathmandu +5:45 labels, Berlin in both DST seasons in the prompt's offset comparison, Europe/Kiev vs Europe/Kyiv (no prompt), a device zone of UTC (no prompt).
- **Privacy:** settings hold no sensitive data. The 🌸 switch stays device-local. The name is user-provided, normalized (bidi controls stripped), never logged, and (Phase 3) shown to linked teachers, which the hint should say then. Logs: account uuid + field names changed, never values. Account delete cascades.
- **i18n:** every string in `app.ftl` / `bot.ftl` with en/ru parity. Plurals for the cap. City names from `cities.yaml`. The language chip labels are in their own language. Choosing a language changes the bot and the Mini App; the Telegram command menu stays in Telegram's language (known limit).
- **Responsiveness:** bot taps take ≤ 2 short statements plus a concurrent callback answer. Mini App edits are optimistic, with one small PATCH each. The Settings chunk is lazy, and Home's initial bundle gets smaller. The tick's candidate query gets simpler (Q24).

## 7. Test plan
- **Domain:** `profile_refresh` keeps a custom name or locale and still updates the other field; `resolve_profile` (blank → Telegram name + flag off, 65 characters → error, emoji/ZWJ kept, bidi stripped, `null` locale → negotiated from `kk` → ru, UTC accepted explicitly, `Etc/GMT+5` rejected); `apply_patch` (KEEP vs None vs value, quiet as a pair, merged check: quiet hours swallowing an enabled 20:00 practice reminder → `InvalidSettings`, the same with practice off → ok).
- **Use case (fakes):** `UpdateProfile` (single write, RETURNING account); `PatchNotificationSettings` writes only the patched columns and leaves a bot change made in between intact; the moon/remind wrappers keep their behaviour; the tick sets `moon_intro_sent_at` only when the intro was delivered, and sends no second intro.
- **Infrastructure (real Postgres):** a concurrent `update_profile` can't overwrite a custom name or locale; patch NULL = default round trip; the 0006 backfill + nulling (a frozen-default row reads the same before and after); upgrade → downgrade → upgrade; `alembic check`.
- **API contract:** PATCH `/me` for each field, nulls, 422s, `*_from_telegram` flags; PATCH settings (omitted vs null vs value; 422 on a quiet-hours conflict); PUT still works and is marked deprecated; OpenAPI regenerated → `gen:api`.
- **Bot handler:** S renders all lines (zone unset; reminders off/on); a language tap re-renders in the new locale; the picker marks the current zone's city and pages; a zone tap overwrites an existing zone; links `s1:v` ↔ `m1:v` / `m1:r` / `r1:v`; malformed data is ignored; **every `s1:` callback ≤ 64 bytes**; en/ru keys exist.
- **Mini App (Vitest):** Settings opens from Home and from the settings button, Back returns; the name saves on blur and blank resets it; a language switch re-renders RU; the zone buttons and the select; disabled quiet-hour options; cap chips; the 🌸 switch shares Stats' key; the travel prompt shows on an offset mismatch only, Keep persists per zone, Switch PATCHes and invalidates; Home no longer has the reminder controls; bundle check.
- **Architecture:** import-linter (domain pure, aiogram only in `bots`).

## 9. Implementation notes and review fixes (2026-10-19)
- **Found while building:** `profile_refresh` copied Telegram's name and language on every contact; it now skips fields chosen in settings, and the SQL refresh keeps them even when it races a settings save.
- **Code-review blocker fixed:** `PATCH /me` wrote all account fields from a stale snapshot, so a name saved together with a language tap could be lost. `ProfileChange.fields` now limits the UPDATE to the sent groups (real-Postgres concurrency test); the Mini App queues its own profile saves.
- **Should-fix fixed:** the bot shows "No quiet hours" instead of 00:00–00:00; the practice-time check reads the row once (one statement fewer); `{"moon": null}` / `{"practice": null}` are refused (422) instead of silently ignored; the travel prompt hides only after a successful switch and shows an error otherwise; a quiet-hours pair CHECK in 0006; the unused `patch_moon` removed; UTC shows in the zone list; practice times inside quiet hours are disabled; chip groups are labelled.
- **Accepted limits:** merged validation isn't one transaction (ADR-0021, known limits). If the old revision sends someone's very first moon reminder in the minutes between migration 0006 and the traffic switch, that person may see the intro once more. City names inside the RU travel prompt fall back to English for zones not in the city list (Q22).
- **Size:** initial JS 114.1 KB gzip (the copy and the travel prompt; the controls moved to a lazy 2.6 KB Settings chunk).
