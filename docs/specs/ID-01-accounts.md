# ID-01 + ID-02 (model): accounts from Telegram, identity model, DB foundation

- Status: accepted (owner accepted every §8 recommendation, 2026-10-18) · Date: 2026-10-18
- Requirements: **ID-01** (account auto-created on `/start` or Mini App open, no forms), **ID-02** (identity provider abstraction; model only, no linking UI), **ID-06** (schema room + silent locale/zone capture only; settings UI out), **NF-02** (≤ $5/mo), **NF-03** (initData verification, policies in the service layer, secrets in Secret Manager, least privilege). Budget: < 300 ms p50 per tap warm (`04 Architecture`).
- Related: ADR-0003, 0004, 0005, 0011, 0012, 0013. New: **ADR-0014** (Postgres access: Supabase, driver, pooling, migrations), **ADR-0015** (accounts, identities and Mini App auth).

## 1. Scope
**In:** DB foundation (engine, schema `tristhana`, Alembic, migrate job, CI Postgres), `account` + `identity` tables, `EnsureAccount` and `RecordDeviceTimezone` use cases, first policy module, bot middleware (every private update resolves the account), Mini App initData auth, `GET /api/v1/me`, `POST /api/v1/me/device-timezone`, Mini App greets with the server-side name and reports its zone once, `GET /api/v1/health/db` for keep-warm.
**Out:** linking a second identity (UI and use case), ID-06 settings screens, explicit language choice in onboarding, travel prompt, platform-admin flag (ID-05), account delete/export (ST-09), app-level encryption (no sensitive field yet; lands with PR-05 ladies' holiday), seed catalog in DB (defer to PR-03, Q3), DB `update_id` dedupe (Q6).

## 2. Flows and copy
- **Bot:** any private message or callback → middleware builds an `ExternalProfile` from `from_user` (id, first_name, language_code; bots ignored) → `EnsureAccount` → `account` injected into handler data. `/start`, `/help`, fallback reply in `account.locale` (same greeting as today; no new prompt). First contact creates the account silently.
- **Mini App:** open → paint with unverified `initDataUnsafe` name (as now) → `GET /api/v1/me` (creates on first open) → greeting switches to `me.display_name`, Fluent locale switches to `me.locale` → if `me.timezone` is null, `POST /me/device-timezone` with `Intl…timeZone` (once per session, fire-and-forget from the UI's view).
- **Failures:** DB down → bot replies `error-temporary`; API 503 → existing `home-server-offline`. Auth expired → `session-expired` screen.
- **Copy (new keys; polished by ux-writer, RU «ты»):** `bot.ftl`: `error-temporary` = "Sorry, I've hit a small hiccup on my side. Please try again in a minute 🙏" / «Прости, у меня небольшая заминка. Попробуй ещё раз через минуту 🙏» · `app.ftl`: `session-expired` = "This session has expired. Close Tristhana and open it again from the bot." / «Сессия истекла. Закрой Тристхану и открой её снова из бота.»

## 3. Design
**Domain (`domain/accounts.py`, pure dataclasses).** `IdentityProvider(StrEnum)`: `telegram` (later `email`, `google`, `apple`). `IdentityKey(provider, provider_user_id: str)` (Telegram id as text, so every provider fits). `ExternalProfile(key, display_name: str | None, language_code: str | None)`. `Account(id: UUID, display_name: str | None, locale: Locale, timezone: str | None, last_seen_at)`. Rules: `normalize_display_name` (strip control chars, collapse spaces, ≤ 64 chars, blank → None); `new_account(profile)` (locale via existing `negotiate_locale`); `profile_refresh(account, profile, now) -> ProfileUpdate | None` (write only if name or locale changed or `last_seen_at` older than 24 h); `parse_timezone(name)` (IANA via `zoneinfo`; rejects `Etc/GMT±N` fixed offsets and garbage; `UTC` allowed); `device_timezone_update(account, tz)` (sets only when unset; changing a set zone is ID-06's travel prompt).
**Application.** Ports (`application/ports/accounts.py`): `AccountRepository` (`find_by_identity`, `create_with_identity` raising `IdentityTaken`, `update_profile`, `set_timezone`), `UnitOfWork` (async context manager: `accounts`, `commit()`), `Clock`. Errors: `StorageUnavailable`. Use cases (`application/accounts.py`): `EnsureAccount(profile) -> Account` (find → maybe refresh → else create; on `IdentityTaken` re-find: concurrent first contact), `RecordDeviceTimezone(principal, tz) -> Account`. Policies (`application/policies.py`): `Principal(account_id)`; `require_self(principal, account_id)`; every future cross-account read (teachers) gets a named policy here. `StartUseCase` now takes the `Account` and returns its locale.
**Infrastructure (`infrastructure/db/`).** SQLAlchemy 2 **Core** (tables in `MetaData(schema="tristhana")`, no ORM, explicit queries, no lazy loads), asyncpg, engine built in the lifespan (lazy import) with one warm-up connection under startup CPU boost (2 s timeout, warning on failure, startup never blocks on the DB). Hot path = **one round trip**: `SELECT a.* FROM identity i JOIN account a … WHERE (provider, provider_user_id) = (…)`. Refresh write ≈ once per user per day. Create = **one atomic statement**: `WITH a AS (INSERT INTO account … RETURNING *), i AS (INSERT INTO identity SELECT a.id, … FROM a) SELECT * FROM a`; a unique violation means a concurrent create, so re-select (no orphans, no explicit transaction). Connection errors map to `StorageUnavailable`. Migrations: Alembic inside the package (`infrastructure/db/migrations`), `tristhana-migrate` script (`pg_advisory_lock`, `upgrade head`). Pooling, roles, region, migrate job: ADR-0014.
**API.** `api/auth.py` (stdlib only): parse `Authorization: tma <raw initData>`, verify HMAC-SHA256 (secret = HMAC("WebAppData", bot_token); all fields except `hash`, sorted, `\n`-joined; `compare_digest`), `auth_date` ≤ 24 h old and ≤ 60 s in the future, then `EnsureAccount` → `Principal`. No JWT, no session table (ADR-0015). Use cases reach the API via `app.state` (wired by `main.py`; `api` never imports `infrastructure`).

| Method, path | Auth | Request | Response |
|---|---|---|---|
| `GET /api/v1/me` | initData | none | 200 `Me {id: uuid, display_name: str \| null, locale: "en"\|"ru", timezone: str \| null}` |
| `POST /api/v1/me/device-timezone` | initData, self | `{timezone: str}` | 200 `Me`; 422 `{code: "invalid_timezone"}` |
| `GET /api/v1/health/db` | none, hidden from OpenAPI | none | 200 `{status: "ok"}` / 503 (keep-warm target, `SELECT 1`) |

Auth errors: 401 `{code: "auth_missing" \| "auth_invalid" \| "auth_expired"}`; DB down: 503 `{code: "unavailable"}`. OpenAPI declares an `apiKey` header scheme so the generated client knows. `/api/v1/health` stays DB-free.
**Bot.** `bots/telegram/middleware.py`: outer middleware on `message` and `callback_query` (private chats), calls `EnsureAccount`, sets `data["account"]`; on `StorageUnavailable` returns `SendMessage(error-temporary)` without calling the handler. No business logic in handlers.
**Mini App.** `openapi-fetch` middleware adds `Authorization: tma <raw initData>` to every request; `useMe()` query (`staleTime: Infinity`); Home uses `me.display_name`; `L10nProvider` prefers `me.locale`; 401 `auth_expired` → `session-expired` screen. Dev browser mock: Q5.
**Settings.** `database_url: SecretStr | None` (unset → DB features return 503/`error-temporary`, app still starts: openapi dump, container smoke), `db_pool_size = 3`, `db_max_overflow = 2`.

## 4. Ops (☁️ owner only, in order; dry-run first)
1. Create the Supabase project (free plan, **eu-central-1 Frankfurt**, next to europe-west3), generated DB password kept in your password manager. **Disable the Data API** (we use plain Postgres only). Download the project's **CA certificate** (Database → SSL Configuration) and commit it as `infra/supabase/certs/supabase-ca.crt` (public, not a secret; PR CI fails until it is there). Check it once: `psql "postgresql://postgres.<ref>@<pooler-host>:5432/postgres?sslmode=verify-full&sslrootcert=infra/supabase/certs/supabase-ca.crt" -c 'select 1'`.
2. Run the reviewed `infra/supabase/roles.sql` in the SQL editor: creates login role `tristhana_app` (password you generate) with no DDL rights.
3. `infra/gcp/bootstrap.sh` (dry-run, then apply): secret containers `database-url` (app role, session pooler) and `database-url-migrate` (`postgres` role, session pooler); SA `tristhana-migrate` with access to the migrate secret only; runtime SA → `database-url` only; deployer `actAs` the migrate SA; keep-warm URI → `/api/v1/health/db`.
4. Add both secret values via stdin (`gcloud secrets versions add … --data-file=-`), never pasted to an agent.
5. Merge: deploy runs `gcloud run jobs deploy tristhana-migrate` + `execute --wait` with the new image, then the service deploy with `DATABASE_URL=database-url:latest`.

## 5. Migration
`0001_accounts`: `CREATE SCHEMA tristhana`; grants `USAGE` + default `SELECT, INSERT, UPDATE, DELETE` on tables to `tristhana_app`; `account(id uuid pk default gen_random_uuid(), display_name text null check (char_length ≤ 64), locale text not null check in ('en','ru'), timezone text null, created_at/updated_at/last_seen_at timestamptz not null default now())`; `identity(provider text check in ('telegram'), provider_user_id text, account_id uuid not null references account on delete cascade, created_at timestamptz, primary key (provider, provider_user_id))` + index on `account_id`. Text + CHECK, not PG enums (adding a provider is a one-line migration). Rules: migrations are expand/contract (the old revision keeps serving while the job runs); `alembic check` in CI keeps tables and migrations in sync.

## 6. Cross-cutting checks
- **Time zones:** instants `timestamptz` UTC; user zone IANA text, null until the device reports it, never guessed now, fixed offsets rejected; nothing displayed yet.
- **Privacy/security:** stored from Telegram: numeric id, first name, negotiated locale. **Not** stored: phone, username, last name, photo, raw language code, initData. `last_seen_at` written at most daily. Logs carry the account uuid, never Telegram ids, names or initData. Separate app/migrate DB roles and SAs; TLS to Supabase with the bundled Supabase CA (verify-full); Data API off; own schema. Policies in `application/policies.py`. No encrypted fields yet.
- **i18n:** two new keys, en/ru parity tests; locale comes from the account, negotiation stays the single rule.
- **Responsiveness:** warm tap = 1 DB round trip (Frankfurt ↔ Frankfurt, ~1–3 ms + Supavisor hop) → target bot server time < 20 ms, `/me` < 30 ms. Engine + asyncpg imported in the lifespan, warm connection at startup, `pool_pre_ping` (~1 RTT, protects against connections dropped while CPU was throttled), `pool_recycle=600`. Keep-warm via `/health/db` keeps both the instance and Supabase active (prevents the free-tier pause after ~1 week idle). Log `db_ms` per request; record p50 in `04 Architecture`.
- **Cost:** Supabase free ($0), migrate job seconds per deploy, 4 secrets (within the 6 free versions). Unchanged ≈ $0–3/mo.

## 7. Test plan
- **Domain:** name normalization (emoji, control chars, 200 chars, blank); `profile_refresh` (no change → None; locale change; name change; 23 h vs 25 h); `parse_timezone` (`Asia/Almaty`, `Asia/Kolkata`, `Asia/Kathmandu`, `UTC` ok; `Etc/GMT+5`, `+05:00`, `Mars/Base` rejected); device zone set only when unset.
- **Use case (in-memory fake UoW + fixed clock):** first call creates; second does no write; stale → one update; `IdentityTaken` once → returns the other account; `StorageUnavailable` propagates.
- **Infrastructure (real Postgres 17):** CI service container in `backend.yml`; locally `podman run postgres:17` (documented in `.env.example`); schema via `alembic upgrade head` once per session, each test in a rolled-back transaction. Repo find/create/update; two concurrent `EnsureAccount`s → one account, no orphan rows; upgrade → downgrade → upgrade; `alembic check` clean. Marked `db`; required in CI, skipped locally without `TEST_DATABASE_URL`.
- **initData:** valid; tampered field; other bot's token; missing hash; 25 h old; future `auth_date`; parity with aiogram's `check_webapp_signature` (test-only import).
- **API contract:** `/me` without header / bad / expired → 401 codes; valid → 200 and creates; repeat → same id; device-timezone set / kept / 422; DB down → 503; `/health` never touches the DB; OpenAPI has the security scheme; `/health/db` hidden.
- **Bot handler:** middleware injects the account (fake use case); `/start` replies in `account.locale`; `StorageUnavailable` → `error-temporary`, handler not called; group chats and bot senders ignored.
- **Mini App (Vitest):** auth header on every request; name from `/me`; `session-expired` on 401; zone posted once only when null; no calls outside Telegram.
- **Architecture:** import-linter: `sqlalchemy`, `asyncpg`, `alembic` only in `infrastructure`; container smoke still passes without `DATABASE_URL`; image ≤ 250 MB.

## 8. Open questions for the owner
1. **Pooler:** Supavisor **session mode (port 5432, IPv4)** with asyncpg and a small pool (≤ 5 per instance × 2 instances)? Recommended: yes. Direct connections are IPv6-only (Cloud Run egress is IPv4 without extra VPC setup); transaction mode breaks asyncpg's prepared statements.
2. **Migrations:** a Cloud Run Job (`tristhana-migrate`) run by the deploy pipeline before the service deploy, with its own DB role and SA? Recommended: yes (not at startup: slower cold starts and racing instances; not from GitHub: DB credentials would leave Secret Manager).
3. **Seed catalog in DB:** defer to PR-03 (the first feature that reads it)? Recommended: defer; nothing reads it yet.
4. **Mini App auth:** send raw initData on every request (`Authorization: tma …`), 24 h max age, no JWT? Recommended: yes (stateless, no extra round trip, no signing key). This replaces "initData → JWT" in `04 Architecture`; JWT returns only for future web/mobile clients.
5. **Dev Mini App in the browser:** a dev-only `GET /dev/telegram-init-data` (mounted only when `APP_ENV=dev`, signs a fake user with the dev bot token) that the mock uses? Recommended: yes (alternative: a CLI that prints initData to paste into `.env.local`, expiring daily).
6. **`update_id` dedupe in DB:** keep the in-memory dedupe until the first non-idempotent handler (PR-01), instead of a write on every update now? Recommended: yes.
7. **Device zone:** capture it silently now when the profile has none (never overwrite)? Recommended: yes; PR-01 needs a local date.
8. **Stored name:** Telegram first name only (no last name, no username)? Recommended: yes; editable in ID-06.
9. **Backups:** the Supabase free plan has no backups we can rely on (to verify at project creation). Add a weekly `pg_dump` → Cloud Storage job before the private beta (separate task)? Recommended: yes.

## 9. Implementation notes (deviations from §3)
- **No `UnitOfWork` port.** Every repository method is one atomic statement on an AUTOCOMMIT connection (create = one CTE), so a transaction object would only add BEGIN/COMMIT round trips. A use case that needs several writes in one transaction adds it then. The `Storage` port bundles lifecycle (`start`/`stop`), `ping` and `accounts`.
- **`application/policies.py` holds only `Principal`.** Every operation today acts on the caller's own account, which the API resolves from initData, so `require_self` would have no caller. Named policies arrive with the first cross-account read (ST-06).
- **`StartUseCase` removed.** `/start`, `/help` and the fallback read `account.locale` from the middleware-injected account.
- **The account locale follows Telegram's `language_code`** on every refresh until ID-06 adds an explicit choice (then the refresh must stop overriding it).
- **Without `DATABASE_URL`** the app uses `UnconfiguredStorage`: startup, OpenAPI dump and the container smoke test still work. The bot replies `error-temporary` and the API returns 503 `unavailable`.
- **TLS:** `DATABASE_CA_FILE` points to Supabase's CA, which the image ships from `infra/supabase/certs/` (the owner downloads it when creating the project).
- **Measured locally** (Postgres 17 in a container, warm, pre-ping + one query): `/me` p50 2.9 ms, webhook `/start` p50 3.0 ms.
- **Middleware is inner, not outer** (§3 said outer): it runs only after a handler's filters matched, so group chats and unhandled updates cost no DB round trip.
- **`db_ms` per request is not logged yet** (§6). The webhook already logs total handling time per update; per-query timing comes with the first multi-query feature.
- **Review fixes (code-reviewer, 2026-10-18):** server-side "unavailable" SQLSTATEs (08, 53, 57 incl. statement timeout, 55P03, XX000) map to `StorageUnavailable`; `hide_parameters=True` keeps ids and names out of error logs; only unique violations count as `IdentityTaken`; `/health/db` queries `tristhana.account`, so missing grants fail the deploy smoke; `roles.sql` also grants idempotently if run after 0001; `/dev/telegram-init-data` needs `DEV_INIT_DATA=true` (refused in prod); prod refuses a `DATABASE_URL` without `DATABASE_CA_FILE`; a device reporting `UTC`/`Etc/UTC` leaves the zone unset (UTC only as an explicit ID-06 choice); `Etc/UTC` normalizes to `UTC`.
- **Follow-ups (nits, not done):** canonicalize ICU legacy zone aliases (`Asia/Calcutta` → `Asia/Kolkata`) when zone labels are first displayed; consider `--no-traffic` deploy + smoke + `update-traffic` for zero-risk rollouts.
